# 08 · 排障与验收

本章先按症状定位问题，再提供上线前必须在真实环境执行的验收清单。排障时保留本地
数据和服务端证据，不要通过关闭 RLS、公开 Bucket、提交 Secret 或删除用户内容来
快速绕过问题。

## 1. 安装与构建

| 症状                   | 检查                                  | 安全处理                                      |
| ---------------------- | ------------------------------------- | --------------------------------------------- |
| `pnpm` 不存在          | `pnpm --version`                      | 从官方渠道安装，重新打开终端                  |
| 依赖安装失败           | Node 版本、网络、仓库根目录、lockfile | 使用 Node 22+，继续用 pnpm，不混用包管理器    |
| 3000 端口占用          | 启动日志                              | `pnpm dev -- --port 3001`，同步更新 Auth 回调 |
| 类型检查失败           | 第一条 TypeScript 错误                | 修复源码，不用 `skipLibCheck` 掩盖项目错误    |
| Build 成功但浏览器异常 | 构建时公开变量、缓存                  | 修改 `NEXT_PUBLIC_` 变量后重新构建            |
| 页面刷新后草稿丢失     | 无痕模式、站点数据、IndexedDB         | 使用正常 Profile，确认未清理站点数据          |

## 2. 环境变量

| 症状               | 检查                                       | 预期                                         |
| ------------------ | ------------------------------------------ | -------------------------------------------- |
| 登录入口不出现     | 两个 `NEXT_PUBLIC_SUPABASE_*` 是否同时设置 | URL 与 publishable key 都存在，并已重启/部署 |
| 交付版本提示未配置 | `SUPABASE_SECRET_KEY`                      | 仅服务端存在，修改后重新部署                 |
| CAPTCHA 不显示     | `NEXT_PUBLIC_TURNSTILE_SITE_KEY`           | 使用当前环境对应 Site Key                    |
| AI 功能全部关闭    | `NEXT_PUBLIC_AI_ENABLED`                   | 只有精确 `false` 才全局关闭                  |
| GA 未加载          | `NEXT_PUBLIC_GA_MEASUREMENT_ID`            | Production 填写 `G-...` 并重新部署           |
| 修改变量无效       | Vercel 环境范围和部署时间                  | 变量只影响之后的新部署                       |

不要把 server secret 临时改名为 `NEXT_PUBLIC_SUPABASE_SECRET_KEY`。这会把高权限凭据
暴露到浏览器。

## 3. Magic Link 与回调

| 症状                         | 检查                                                  | 处理                                         |
| ---------------------------- | ----------------------------------------------------- | -------------------------------------------- |
| 邮件未收到                   | Supabase Auth Logs、SMTP、Resend Logs、垃圾箱         | 确认自有 SMTP 和发信域已验证                 |
| Email address not authorized | 是否仍用 Supabase 默认 SMTP                           | 配置 Custom SMTP，默认服务只适合项目成员测试 |
| 点击后回 localhost           | Supabase Site URL、模板链接                           | 将 Site URL 改为生产域名，重新发送新邮件     |
| redirect not allowed         | Redirect URLs 是否包含当前 Origin 的 `/auth/callback` | 添加精确回调；Preview 用测试项目受控规则     |
| 链接已失效                   | 是否过期或已使用                                      | 重新发送，不重复使用旧链接                   |
| 回调后仍未登录               | `/auth/callback` 日志、cookie、code exchange          | 检查 HTTPS、域名和 Supabase SSR 配置         |

## 4. Google OAuth

| 症状                    | 检查                               | 处理                                                 |
| ----------------------- | ---------------------------------- | ---------------------------------------------------- |
| `redirect_uri_mismatch` | Google Authorized redirect URI     | 使用 Supabase `/auth/v1/callback`，不是应用 callback |
| Origin 不允许           | Authorized JavaScript origins      | 添加当前本地或生产 Origin，不带路径                  |
| 只有部分账号可登录      | Consent Screen Audience            | 测试状态添加 Test users，生产前完成所需发布流程      |
| Supabase Provider 报错  | Client ID / Secret                 | 重新粘贴到 Supabase，不放进 Vercel                   |
| 登录回错域名            | Supabase Site URL 与 Redirect URLs | 同步生产域名并发起新流程                             |

## 5. SMTP 与模板

| 症状              | 检查                              | 处理                                       |
| ----------------- | --------------------------------- | ------------------------------------------ |
| Resend 域名未验证 | SPF、DKIM、DNS 传播               | 使用 Resend 给出的精确记录，不自创值       |
| 邮件进垃圾箱      | SPF/DKIM/DMARC、From 域、链接域   | 分离 Auth 子域，保持品牌和链接一致         |
| 按钮指向原项目    | 模板中的硬编码域名                | 修改仓库模板副本后重新粘贴                 |
| 新用户文案错误    | Confirm signup 模板               | 不要把 Magic Link 模板粘到两个位置         |
| 发送被限流        | Supabase Rate Limits、Resend 日志 | 调查请求来源，配置 CAPTCHA，不盲目提高限制 |

## 6. Turnstile

| 症状                    | 检查                                     | 处理                                            |
| ----------------------- | ---------------------------------------- | ----------------------------------------------- |
| 所有登录都失败          | Supabase 已开 CAPTCHA，但前端无 Site Key | 配置对应 Site Key 并重新部署                    |
| Widget 成功但服务端拒绝 | Site Key 与 Secret 不配对                | 使用同一 Widget 的 Key 对；测试项目使用测试组合 |
| 本地测试失败            | 生产 Secret 不接受 dummy token           | 使用独立测试 Supabase 项目和官方测试 Key        |
| Hostname 错误           | Widget 允许域名                          | 生产只添加受控生产域名                          |
| 重试仍失败              | token 已过期或使用过                     | 重置 Widget，生成新 token                       |

## 7. Supabase、RLS 与同步

| 症状                     | 检查                             | 安全处理                                      |
| ------------------------ | -------------------------------- | --------------------------------------------- |
| 表不存在                 | migration history                | 按 `0001`、`0002`、`0003` 顺序应用            |
| 工作区 revision 检查失败 | `0003`、函数权限、触发器         | 补齐第三个 migration，不在客户端伪造版本      |
| 用户能看到他人数据       | RLS 与 owner policy              | 立即停止公开访问，修复并做两账号复测          |
| 首次登录出现本地内容     | 工作区切换流程和缓存             | 停止验收，确认加载期间不回退显示本地数据      |
| 某条目同步暂停           | 是否存在冲突                     | 比较后明确选择本机、云端或另存新草稿          |
| 所有条目停止同步         | 网络、`cloud_controls`、队列错误 | 确认是增长冻结、额度还是连接错误              |
| 配额分类错误             | PostgREST message/code           | 检查 migration 和应用错误映射，不删除本地原文 |
| 退出被阻止               | 未同步或冲突内容                 | 重试同步；必要时明确确认放弃缓存              |

## 8. Storage 与交付版本

| 症状                    | 检查                                    | 处理                                         |
| ----------------------- | --------------------------------------- | -------------------------------------------- |
| Bucket 不存在           | `0001` 是否成功                         | 应用 migration，名称必须为 `design-releases` |
| 直接 Storage URL 为 403 | Bucket 是否 private                     | 这是预期；通过签名下载 Route Handler         |
| 浏览器可直接列出对象    | Storage policy 或 Public 开关           | 立即改回 private 并移除浏览器访问 policy     |
| 无法创建版本            | server secret、来源同步、派生状态、额度 | 分别检查，不上传浏览器自制 ZIP 绕过          |
| 版本一直 pending        | 函数日志、元数据、Storage 对象          | 先核对对象和请求 ID，再设计补偿              |
| 下载校验失败            | ZIP 摘要、大小、manifest                | 停止打开，保留证据并重新生成                 |
| 第三个版本未清理旧版    | 新版本是否完全成功                      | 只有完成后才应清理；失败时保留旧版是预期     |
| 删除来源后版本仍存在    | 产品保留规则                            | 到 `/releases` 单独删除                      |

## 9. 云端额度

| 错误                        | 含义                    | 用户可继续做什么                 |
| --------------------------- | ----------------------- | -------------------------------- |
| `RICO_QUOTA_DOCUMENTS`      | 草稿超过 75             | 编辑、导出、删除，不能新增云草稿 |
| `RICO_QUOTA_LIBRARY`        | 设计库超过 50           | 编辑、导出、删除，不能新增云条目 |
| `RICO_QUOTA_MARKDOWN_BYTES` | Markdown 合计超过 1 MiB | 缩小或删除云端内容               |
| `RICO_CLOUD_GROWTH_FROZEN`  | 运维已关闭新增用量      | 读取、下载、删除和不增长的修改   |
| `RICO_QUOTA_RELEASE_COUNT`  | 完成版本达到 100        | 删除不需要版本                   |
| `RICO_QUOTA_RELEASE_BYTES`  | 交付包合计超过 5 MiB    | 下载或删除已有版本               |
| `RICO_RELEASES_FROZEN`      | 运维暂停新版本          | 继续本地导出和管理已有版本       |
| `RICO_RATE_PUBLISH`         | 一小时生成尝试过多      | 等待窗口恢复                     |
| `RICO_RATE_DOWNLOAD`        | 一小时下载尝试过多      | 等待窗口恢复                     |

任何云端配额错误都不应删除本地原件或阻止本地导出。

## 10. AI

| 症状                   | 检查                          | 处理                                |
| ---------------------- | ----------------------------- | ----------------------------------- |
| 浏览器直连 CORS 错误   | Provider 是否允许浏览器请求   | 切换同源代理                        |
| 代理拒绝地址           | HTTPS、私网、DNS、白名单      | 使用公开合法端点，不关闭 SSRF 校验  |
| Key 有效但模型失败     | 模型权限和 endpoint           | 在 Provider 控制台确认模型 ID       |
| `401` / `403`          | Key 或套餐权限                | 更新配置，不把 Key 发到 Issue       |
| `429` / `503` / `1305` | 服务繁忙                      | 稍后重试或换标准端点                |
| 没有可见正文           | reasoning 分离或响应中断      | 关闭 Thinking、换模型或标准 GLM API |
| 模型列表失败           | Provider 不支持兼容 `/models` | 手动输入模型 ID                     |
| 修改没有写入           | 仍处于提案状态                | 查看差异后点击明确应用              |

## 11. 网址抓取

| 症状           | 检查                     | 处理                               |
| -------------- | ------------------------ | ---------------------------------- |
| URL 被拒绝     | 协议、凭据、hostname、IP | 只使用公开 HTTPS URL               |
| DNS 指向私网   | DNS 解析结果             | 停止请求，检查域名或 DNS rebinding |
| 页面需要登录   | 目标站点访问方式         | 不向抓取器提供账号 cookie 或密码   |
| 内容类型不支持 | Response Content-Type    | 使用公开 HTML 或 DESIGN.md         |
| 60 秒超时      | 站点响应和 Vercel 日志   | 换公开稳定来源，不无限延长超时     |
| 结果缺少样式   | 网站动态加载或阻止抓取   | 人工补充并复核 AI 推断             |

## 12. 上线前真实验收

### A. 纯本地

- [ ] 不配置环境变量也能创建、编辑、刷新、导入和导出。
- [ ] 清楚提示数据只在当前设备。
- [ ] AI 和登录缺失不破坏核心界面。
- [ ] 中文、英文、桌面和窄屏没有关键操作溢出。

### B. AI

- [ ] 至少一个 Provider 完成测试连接、分析和修订提案。
- [ ] 打开面板不发送文档。
- [ ] 放弃提案不修改原文，应用后差异一致。
- [ ] 错误响应不覆盖当前文档。
- [ ] 代理拒绝 localhost、私网和白名单外主机。

### C. 两账户与两设备

- [ ] A、B 互相不能读取、修改或删除数据。
- [ ] 登录前本地 AB，登录后只显示云端 CD，不发生内容闪现或自动合并。
- [ ] 选择复制后云端得到新 ID，退出后本地 AB 仍在。
- [ ] 同账号两设备修改同一条目时，只暂停冲突条目。
- [ ] 三种冲突选择都与说明一致。
- [ ] 离线编辑、重连和账号直接替换不会泄露前一账号缓存。

### D. 交付版本

- [ ] 未登录不出现可用的私有交付操作。
- [ ] 来源未同步或派生失败时不能创建。
- [ ] ZIP 内容、摘要、大小和 manifest 正确。
- [ ] 第三个完成版本后只保留最新两个。
- [ ] 失败不会删除已有完成版本。
- [ ] 另一个账号不能下载、删除或恢复。
- [ ] 恢复创建新草稿，不覆盖来源。

### E. CAPTCHA、邮件和删除账户

- [ ] 有效、无效、过期和重复 CAPTCHA token 行为正确。
- [ ] Magic Link、新用户确认和 Google 登录回到正确域名。
- [ ] 邮件 SPF/DKIM 通过，模板无原部署域名残留。
- [ ] 删除账户清理 Storage、业务数据、Auth 和设备缓存。
- [ ] 部分失败可以安全重试，界面不假装完成。

### F. 移动端与窄屏

- [ ] 在真实手机或浏览器设备模拟中检查首页、文档列表、编辑器、账户弹窗和交付版本页。
- [ ] 源码输入、视图切换、搜索、导出和 AI 面板不被键盘或安全区域遮挡。
- [ ] 长文件名、错误提示和用量文字不会造成横向溢出，主要操作无需精确悬停。
- [ ] Magic Link 从手机邮件返回后能完成会话；Google OAuth 返回的仍是同一生产域名。
- [ ] 至少完成一次手机新建、编辑、刷新恢复和下载 `DESIGN.md` 的闭环。

## 13. 验收记录

每次正式验收记录：

- 日期、commit SHA、部署 URL 和环境；
- Supabase migration 版本；
- 浏览器、设备和账号组合；
- 每项结果与证据位置；
- 失败日志的请求 ID，不记录 Secret 或正文；
- 修复 commit 和复测结果。

只有有证据的项目才能标记完成。供应商 Dashboard 中“已启用”不等于端到端流程通过。
