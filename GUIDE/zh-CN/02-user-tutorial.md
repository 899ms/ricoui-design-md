# 02 · 完整使用教程

这份教程从第一份 `DESIGN.md` 开始，依次介绍编辑、检查、AI、设计库、品牌参考、
导出、云同步、冲突处理和交付版本。除明确标记的章节外，所有操作都可以在纯本地
模式完成。

## 1. 先理解数据模型

RICOUI DESIGN 将 `DESIGN.md` 视为唯一可编辑真源：

```text
创建或导入 DESIGN.md
        ↓
编辑原文或已识别的结构化区块
        ↓
由当前原文生成预览、JSON、CSS 和 ZIP
        ↓
保存到设计库，或按需创建私有交付版本
```

结构化控件只修改已经识别的 Markdown 区块。未知章节和普通 Markdown 会原样保留，
不会因为切换视图而删除。

### 主要页面

| 路径         | 用途                                             |
| ------------ | ------------------------------------------------ |
| `/`          | 新建、导入、网址生成、最近草稿、设计库和品牌入口 |
| `/editor`    | 编辑当前文档，查看预览、诊断、AI 和导出          |
| `/documents` | 搜索、筛选、批量管理草稿                         |
| `/library`   | 管理个人设计库                                   |
| `/brands`    | 浏览内置只读品牌参考                             |
| `/search`    | 跨草稿、设计库和品牌搜索                         |
| `/releases`  | 管理登录账户的私有交付版本                       |
| `/guide`     | 应用内简明帮助                                   |

## 2. 创建第一份 DESIGN.md

### 需要什么

- 已按[快速开始](./01-quick-start.md)启动应用；
- 不需要账号、环境变量或 AI Key。

### 操作步骤

1. 打开首页，选择“新建草稿”。
2. 在编辑器的“文档”视图切换到“源码”。
3. 输入名称、描述、主题、颜色、字体、间距和组件说明。
4. 等待顶部状态显示内容已保存到本机。
5. 切换到“阅读”，检查 Markdown 的实际阅读效果。
6. 切换到“结构化”，修改已识别的颜色、字体、字号、间距或圆角。
7. 打开“预览”，检查视觉结果。

### 可直接使用的最小示例

```markdown
# Acme — Design System

> A clear design language for product interfaces.

**Theme:** light

## Tokens — Colors

| Name       | Value   | Token              | Role               |
| ---------- | ------- | ------------------ | ------------------ |
| Brand      | #2563EB | --color-brand      | Primary actions    |
| Background | #FFFFFF | --color-background | Application canvas |
| Text       | #0F172A | --color-text       | Primary text       |

## Tokens — Typography

| Name | Value                                       | Token       | Role      |
| ---- | ------------------------------------------- | ----------- | --------- |
| Sans | Inter, ui-sans-serif, system-ui, sans-serif | --font-sans | Interface |

### Type Scale

| Role | Size | Line Height | Letter Spacing | Token            |
| ---- | ---- | ----------- | -------------- | ---------------- |
| Body | 16px | 1.5         | 0              | --font-size-body |

## Tokens — Spacing & Shapes

### Spacing Scale

| Name | Value | Token     |
| ---- | ----- | --------- |
| 1    | 4px   | --space-1 |
| 2    | 8px   | --space-2 |

### Radius Scale

| Name   | Value | Token       |
| ------ | ----- | ----------- |
| Medium | 8px   | --radius-md |

## Components

### Button

**Role:** Primary action control.

Use the brand color for the primary state and keep one primary action per
surface.

## Do's and Don'ts

### Do

- Keep action labels short and specific.

### Don't

- Do not use multiple primary actions in one panel.
```

不用一次写完所有章节。先建立能解析的骨架，再逐项补全，比从一份巨大文档开始更
容易定位问题。

### 成功表现

- 刷新后草稿仍存在；
- 文档视图能显示大纲和摘要；
- 结构化视图出现与原文对应的控件；
- 修改结构化控件后，源码中的对应表格同步变化；
- 预览使用当前颜色和排版。

### 常见失败

| 现象                   | 处理                                                   |
| ---------------------- | ------------------------------------------------------ |
| 结构化视图不可用       | 检查 H1、Token 章节和 Markdown 表格是否完整            |
| 部分章节没有控件       | 该章节可能是未建模原文；继续在源码中编辑               |
| 切换视图后仍显示旧预览 | 先修复当前解析错误；无效原文期间会保留最后一次有效预览 |
| 刷新后没有草稿         | 检查是否使用无痕窗口、清除了站点数据或禁用了 IndexedDB |

## 3. 导入已有 Markdown

### 需要什么

- 一个或多个 `.md` 文件；
- 单文件最大 500 KB；
- 普通 Markdown 也可以导入，不要求一开始就符合 DESIGN.md 结构。

### 操作步骤

1. 在首页拖入文件，或选择“导入”。
2. 单文件导入成功后会直接打开；批量导入会显示成功、失败和跳过数量。
3. 打开导入指南，查看缺失字段、格式风险和只读建议。
4. 普通 Markdown 可以先以“仅原文”状态保存，之后再补充设计结构。

### 成功表现

- 原文内容完整保留；
- 文件名成为草稿名称，且可以重命名；
- 可解析文档开放结构化和预览；
- 不可解析文档仍能在源码视图继续修复。

### 常见失败

- 扩展名不是 `.md`：先转换为 Markdown 文件；
- 超过 500 KB：拆分无关内容，保留设计规范主体；
- 表格列或分隔线损坏：在源码中修复 Markdown 表格；
- 云端额度已满：本地模式仍可导入，云端工作区需先清理额度。

## 4. 使用四种编辑视图

### 源码

直接编辑完整 Markdown。适合新增未知章节、修复表格、调整 Token 名称和处理结构化
控件尚未覆盖的内容。源码是最终依据。

### 阅读

以排版后的 Markdown 检查章节层级、表格和说明文字。阅读视图不会改变原文。

### 结构化

通过表单、颜色选择器和数值控件编辑已经建模的区块。每个控件只写回对应 Markdown
区域；未建模内容保持不变。源码失效时，结构化编辑会暂停。

### 预览

从当前 `DESIGN.md` 生成设计系统预览。应用内预览不读取品牌包的 `preview.html`；
`preview.html` 只是部分内置品牌资料的独立参考文件。

## 5. 从网站生成 DESIGN.md

### 需要什么

- 一个公开可访问的 HTTPS 网站；
- 已按 [AI 配置](./03-ai-configuration.md)添加并验证 Provider；
- 允许将抓取到的来源材料发送给当前选择的 AI 服务。

### 操作步骤

1. 在首页搜索框或全局搜索中粘贴完整 HTTPS 地址。
2. 选择“从网址生成 DESIGN.md”。
3. 应用先查找公开的 `DESIGN.md`，同时提取页面元信息、可读内容和样式信号。
4. 确认 AI 配置后开始生成；关闭进度面板不会自动取消后台任务。
5. 生成结果会保存为新草稿，不覆盖现有文档。
6. 检查品牌色、字体、Token、组件说明、来源链接和 AI 无法可靠判断的内容。

### 安全边界

应用拒绝 `localhost`、私有 IP、带用户名或密码的 URL，以及解析到私有网络的主机。
网址生成是分析起点，不是网页逐像素复制，也不代表获得原站品牌资产的授权。

### 成功表现

- 进度依次显示来源发现、生成、检查和保存；
- 新草稿包含来源归属；
- 格式有效时可以结构化编辑和预览；
- 有未解决问题时会保存为可修复草稿，并明确锁定不安全的派生导出。

### 常见失败

| 现象         | 处理                                                      |
| ------------ | --------------------------------------------------------- |
| 网址被拒绝   | 使用公开 HTTPS 地址，移除凭据、查询式跳转和私网地址       |
| 无法读取页面 | 检查站点是否阻止抓取、需要登录或返回不支持的内容类型      |
| 模型无正文   | 重试、切换模型，GLM 用户优先使用标准 API 而非 Coding Plan |
| 结果不完整   | 查看问题列表，手动修复或让 AI Assistant 定点修改          |

## 6. 正确使用 AI Assistant

### 什么时候会发送文档

仅打开 AI 面板不会发送内容。以下操作会把当前任务所需内容发送给所选 Provider：

- 运行分析；
- 生成标准化候选；
- 向 AI Assistant 发送问题；
- 从网站生成 DESIGN.md；
- 请求 AI 修复或调整视觉风格。

API Key 和 Provider 配置保存在当前浏览器 IndexedDB，不进入 Supabase 同步数据。

### 推荐工作流

1. 在编辑器打开 AI 工作区。
2. 选择已测试连接的配置。
3. 明确描述目标和不希望改动的范围，例如：
   - “检查颜色 Token 是否有重复语义，不改字体和间距。”
   - “修复阻止 CSS 导出的 Token 名称。”
   - “解释当前文档为什么不能使用结构化视图。”
   - “保留内容，改成克制的黑白编辑风格。”
4. 查看助手识别的意图和预计范围。
5. 如果生成修订，检查完整差异、修改前后能力和剩余问题。
6. 只有确认后点击“应用修订”。放弃提案不会修改原文。

### 成功表现

- 解释类请求只返回说明，不制造无意义修改；
- 修改类请求返回完整候选和可选择的差异；
- 原文变化前始终存在明确确认步骤；
- 应用后源码、预览和导出状态使用同一版文档。

### GLM、Thinking 与 Coding Plan

标准化、Assistant、修复和分析任务会关闭 Thinking；网址生成等复杂任务才会按设置
使用深度思考，且默认关闭。GLM Coding Plan 是实验性兼容入口，可能限流或拒绝非指定
工具。需要稳定使用时优先选择标准 Z.AI / GLM API。

错误码 `1305`、HTTP `429` 或 `503` 通常表示服务繁忙，不等于 API Key 无效。
HTTP `401` 或 `403` 再检查 Key、模型权限、账户套餐和端点。

## 7. 检查并导出

### 导出层级

| 文档状态                 | 可用能力                                |
| ------------------------ | --------------------------------------- |
| 非空普通 Markdown        | 保存、查看、复制、下载原始 Markdown     |
| 可识别 DESIGN.md         | 加上结构化编辑和预览                    |
| Token 与数值通过派生检查 | 加上 `tokens.json`、CSS、ZIP 和交付版本 |

保存资格与派生资格彼此独立。不能导出 CSS 不代表原始 Markdown 不能保存。

### 操作步骤

1. 打开导出菜单，查看当前派生状态。
2. 如有问题，打开问题列表或在源码中修复。
3. 确保每个 Token 有合法名称和值，`var(--token)` 引用最终可解析。
4. 按需导出：
   - `DESIGN.md`：唯一可编辑原文；
   - `tokens.json`：DTCG Token JSON；
   - `variables.css`：CSS custom properties；
   - `theme.css`：Tailwind CSS v4 变量；
   - 文档 ZIP：`DESIGN.md`、标准与原始 Token JSON、两份 CSS 和 `README.md`；
   - 工作台 ZIP：所有草稿，每份草稿一个文件夹。

### 成功表现

- 导出菜单显示文件已就绪；
- JSON 可以解析，CSS 变量名称有效；
- ZIP 内的 `DESIGN.md` 与导出时的当前原文一致。

## 8. 使用设计库、品牌参考和搜索

### 保存到设计库

1. 打开一份非空草稿。
2. 选择“保存到设计库”。
3. 填写名称、描述、可选项目 URL、分类和标签。
4. 从设计库打开后，可更新原条目或另存新版本。

项目 URL 会写入 `DESIGN.md` 的 `**Project URL:**` 行；清空字段时会同步移除。

### 从品牌参考开始

品牌参考是内置只读资料。选择“用作模板”会创建一份自己的草稿，不会修改原品牌包。
这些资料用于学习和分析，不代表官方授权，也不应直接冒充原品牌。

内置品牌库的品牌规范内容来源于 [getdesign.md](https://getdesign.md/) 与
[VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md)，并经过二次解析以适配
本应用的 `DESIGN.md` 工作流。它们仅作学习与分析参考，不表示本项目拥有原始内容，也不表示每个
二次推导值都已获原始品牌确认。

### 批量整理

在草稿或设计库页面进入选择模式。搜索和筛选后，“全选当前结果”只作用于当前结果，
包括尚未滚动加载的匹配项。删除会要求确认；启用云同步时，删除也会进入同步队列。

### 全局搜索

使用导航中的搜索或 `Ctrl K` / `⌘ K`，可同时搜索草稿、设计库和品牌。粘贴网址时
还可以直接开始网站生成任务。

## 9. 开启跨设备同步

### 需要什么

- 部署者已完成 [Supabase](./04-supabase-setup.md)和
  [登录配置](./05-auth-email-captcha.md)；
- 当前设备有可用网络；
- 你理解未登录本地工作区和登录云端工作区互相独立。

### 首次登录

1. 使用 Magic Link 或 Google 登录。
2. 应用隐藏本地内容并加载该账户的云端工作区；加载期间不会把本地内容伪装成云端。
3. 云端加载完成后，选择是否复制本地草稿和设计库条目。
4. 只有勾选项会使用新 ID 复制；不勾选不会删除本地原件。
5. 退出登录后，本地工作区会恢复。

### 日常同步

编辑先写入按账户隔离的设备缓存，再在联网时进入同步队列。离线期间可继续编辑；
恢复网络后应用继续同步。AI Key、Provider 和网址缓存始终留在本机。

### 云端额度

- 75 份草稿；
- 50 个设计库条目；
- 单项 Markdown 250 KiB；
- 账户 Markdown 合计 1 MiB。

达到上限时，本地编辑、读取、导出和删除仍可用；增加云端用量的操作会被阻止。

## 10. 处理同步冲突

当另一台设备更新了同一项目，当前设备继续自动保存本机内容，但暂停该项目的云上传。
其他项目不受影响。

选择“比较并选择”后：

- **使用本机版本覆盖云端**：把当前编辑设为新的云端版本；
- **载入云端版本**：用云端内容替换当前本机差异；
- **另存为新草稿**：保留两份内容，新草稿使用新 ID。

没有确认前，系统不会自动覆盖云端或创建额外冲突副本。旧版本曾自动产生的冲突副本
不会自动删除，可在草稿管理页筛选并人工核对。

## 11. 创建私有交付版本

### 需要什么

- 已登录并联网；
- 当前来源完成云同步；
- Token 和数值通过派生检查；
- 部署者配置了 `SUPABASE_SECRET_KEY` 和私有 `design-releases` Bucket。

### 操作步骤

1. 在编辑器导出菜单选择“生成交付版本”。
2. 服务端读取刚同步的同一版 Markdown，验证来源版本和内容摘要。
3. 服务端确定性生成私有 ZIP 并上传；浏览器不能上传任意文件到该 Bucket。
4. 在 `/releases` 下载、查看、删除，或恢复为新草稿。

### 保留规则

- 单个 ZIP 最大 2 MiB；
- ZIP 解压后的文件合计最大 4 MiB；
- 全部交付版本合计 5 MiB；
- 每账户最多 100 个完成版本；
- 每个来源保留最新两个完成版本；
- 第三个版本完全成功后才清理最旧版本；
- 删除原草稿不会自动删除交付版本；
- 恢复始终创建新草稿，不覆盖当前来源。

交付版本不会生成公开分享链接。下载链接在验证所有权后签发，有效期为 60 秒。

## 12. 备份与退出登录

账户设置可下载草稿和设计库的原始 Markdown 备份，不包含 AI Key、Provider 配置或
设备偏好。云端不是唯一或永久备份，应定期下载原文。

退出登录前应用先尝试同步。同步完成后会清除该账户的设备云端缓存并恢复未登录本地
工作区。如果存在未同步或冲突内容，应先重试；只有明确确认后才放弃缓存并退出。

## 13. 发布前检查清单

- [ ] 源码、阅读、结构化和预览均已检查。
- [ ] Token 名称和值有效，派生文件可生成。
- [ ] AI 建议已经人工复核，文档中没有 Key 或敏感信息。
- [ ] JSON、CSS 和 ZIP 来自同一版 `DESIGN.md`。
- [ ] 已下载原始 Markdown 备份。
- [ ] 如启用同步，已使用另一台设备或独立浏览器验证账号隔离。
- [ ] 如创建交付版本，已下载并检查 ZIP 内容。

部署或运维遇到问题时，继续阅读[排障与验收](./08-troubleshooting-and-acceptance.md)。
