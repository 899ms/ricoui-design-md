# 08 · トラブルシューティングと受け入れ

[ガイド一覧](./README.md) · [English](../en/08-troubleshooting-and-acceptance.md) · [简体中文](../zh-CN/08-troubleshooting-and-acceptance.md)

データを変更したりセキュリティ制御を緩めたりする前に、次の表で診断してください。

| 症状                                   | 確認すること                                          | 安全な対応                                                   |
| -------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------ |
| インストールまたはビルドに失敗する     | Node/pnpm のバージョンと最初の実際のターミナルエラー  | lockfile の状態を確認してから依存関係を再インストールする    |
| サインイン入口が表示されない           | 2 つの公開 Supabase 変数                              | この組を追加して再起動／再デプロイする                       |
| Magic Link が localhost に戻る         | Site URL、redirect URL、メールテンプレート            | 正確な本番 callback を修正して新しいリンクを送る             |
| Google がサインインを拒否する          | Google origin と Supabase callback                    | アプリの callback ではなく Supabase callback を使う          |
| メールが届かない／迷惑メールになる     | Resend の検証済みドメイン、SPF/DKIM/DMARC、レート制限 | プロバイダーが生成した DNS レコードを公開して再テストする    |
| CAPTCHA がすべてのリクエストを拒否する | 対応する Site Key と Supabase Secret                  | 環境ごとに対応する Widget を使う                             |
| 別アカウントのデータが見える           | RLS、owner ID、古いアカウントキャッシュ               | ロールアウトを止め、続行前に所有者分離をテストする           |
| 非公開 Storage URL が 403              | バケットの非公開設定                                  | 想定どおり。所有者確認済みの署名付きダウンロードルートを使う |
| クラウド容量が満杯                     | アカウント使用量とリリースの整理                      | 自分の未使用データを削除する。ローカル編集は引き続き利用可能 |
| AI プロキシが失敗する                  | API キー、モデル、許可リスト、プロバイダー状態        | 再試行、モデル変更、確認済みホスト名リストを更新する         |
| Web サイト取得に失敗する               | 公開 HTTPS アドレスと DNS 結果                        | localhost／プライベートネットワーク保護を回避しない          |
| Vercel リクエストが早期終了する        | 関数ログ、実行時間、プラン                            | URL 取得は 60 秒、AI は 300 秒以内に保つ                     |

## 本番受け入れ

### A. ローカルのみ

- `.env.local` なしで作成、インポート、編集、プレビュー、エクスポートを行う。
- リフレッシュしてドキュメントを開き直し、IndexedDB から復元されることを確認する。

### B. AI

- 設定済みプロバイダーを 1 つ、拒否される private／localhost target、適用前レビューがあるソース変更を確認する。
- プロバイダーエラーにキーやドキュメント内容が露出しないことを確認する。

### C. 2 アカウントと 2 デバイス

- アカウント A がアカウント B のデータを閲覧、変更、ダウンロード、削除できない。
- 初めてクラウドに入る際、選んだローカル項目だけを新しい ID でコピーする。
- オフライン編集と再接続が機能し、競合ソースは明示的なローカル／クラウド／新規保存の解決を待つ。別アカウントのキャッシュを漏らさない。

### D. 納品版

- 同期済みで導出可能なソースから不変の ZIP を作成できる。
- 3 回目のリリース成功後、そのソースには新しい 2 つだけが残る。
- 失敗しても完了済みリリースは保持され、別アカウントはアクセスできない。
- 復元は新しい下書きを作成し、署名付きダウンロードが想定どおり期限切れになる。

### E. 認証、削除、モバイル

- 有効、無効、期限切れ、繰り返し使用した CAPTCHA トークンをテストする。
- 本番ドメインで Magic Link、確認、Google callback をテストする。
- 削除でアプリデータ、非公開オブジェクト、Auth ユーザー、端末キャッシュが消え、部分失敗後も安全に再試行できることを確認する。
- 実機スマートフォンで、新しい下書き、ソース編集、リフレッシュ復元、エクスポート、メールからの復帰を、キーボードやセーフエリアの妨げなくテストする。

日付、コミット SHA、デプロイ URL、マイグレーションバージョン、テストアカウント、結果を記録します。シークレット、セッショントークン、署名付き URL は記録しないでください。
