# 02 · 利用チュートリアル

[ガイド一覧](./README.md) · [English](../en/02-user-tutorial.md) · [简体中文](../zh-CN/02-user-tutorial.md)

## ドキュメントモデル

`DESIGN.md` が正本です。構造化コントロールとプレビューはここから導出され、`tokens.json`、CSS、ZIP は別のソースではなく生成物です。ローカル下書きとサインイン済みクラウドワークスペースは意図的に分離されています。

## 最初のドキュメントを作る

起動済みのローカルアプリケーションが必要です。**新しい下書き**を選択し、次の最小構成でソースを編集します。

```md
# Acme · Design System

> プロダクトの画面のための簡潔なビジュアル言語。

**Theme:** light

## Tokens · Colors

| Name  | Value   | Token         | Role            |
| ----- | ------- | ------------- | --------------- |
| Brand | #2563EB | --color-brand | Primary actions |

## Tokens · Typography

### Type Scale

| Role | Size | Line Height | Letter Spacing | Token            |
| ---- | ---- | ----------- | -------------- | ---------------- |
| Body | 16px | 1.5         | 0              | --font-size-body |

## Components

### Button

**Role:** Main action control.
```

成功の目安は、ソース、閲覧、プレビューの各ビューに有用な内容が表示されることです。構造化フィールドが使えない場合は、見出しや表が認識されるまでソースを編集してください。

## インポートと編集ビュー

複数の `.md` ファイルをインポートできます。各ファイルの上限は 500 KiB です。4 つのビューにはそれぞれ異なる役割があります。

| ビュー     | 目的                                             |
| ---------- | ------------------------------------------------ |
| ソース     | 正本の Markdown。任意の文章を安全に編集する場所  |
| 閲覧       | レンダリングされた Markdown の確認               |
| 構造化     | 認識・モデル化されたセクションのみのコントロール |
| プレビュー | 認識されたデザイン意味論の視覚的な解釈           |

未知のソース内容も保持されます。生成された JSON や CSS を代替ソースとして編集しないでください。

## Web サイトから生成し、AI を使う

先に [AI 設定](./03-ai-configuration.md) でプロバイダーを設定します。公開 HTTPS URL を貼り付け、明示的に生成を開始してから、新しい下書きを確認します。アプリケーションは localhost、プライベートネットワーク、認証情報を含む URL を拒否します。Web サイトからの下書きは分析の出発点であり、ブランドを複製する許可や、推測値が正確であるという主張ではありません。

AI Assistant がドキュメントを送信するのは、分析、修復、正規化、編集を明示的に要求した後だけです。完全な差分を確認し、明示的に適用してください。AI の応答がソースを黙って上書きすることはありません。

## ライブラリ、Brands、検索

再利用したい下書きは、名前、説明、任意のプロジェクト URL、タグ、カテゴリとともにライブラリへ保存します。ライブラリは空でない Markdown をすべて保持しますが、構造化プレビューと派生エクスポートが使えるのは、ドキュメントが各要件を満たす場合だけです。Brands は読み取り専用の参照資料です。Brand から下書きを作成しても、元の資料は編集されません。

組み込みの Brand 参照は [getdesign.md](https://getdesign.md/) と [VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md) を基にし、このアプリケーションの `DESIGN.md` ワークフロー向けに二次解析したものです。学習と分析に使用してください。元資料の所有権や、すべての導出値が元ブランドで確認済みであることを示すものではありません。

検索、タグ、カテゴリ、一括選択削除を使って、自分の下書きとライブラリ項目を管理します。一括削除の前に選択内容を確認してください。

## エクスポートと納品版

常に `DESIGN.md` をエクスポートしてください。導出チェックに通る場合は、DTCG JSON、CSS 変数、Tailwind CSS、ローカル ZIP もエクスポートできます。納品版は別物です。同期済みのソースからサーバーが作成する、不変かつ非公開の ZIP です。

納品版を作成するには、サインイン済みかつ同期済みのアカウント、導出可能なドキュメント、デプロイ管理者が設定したサーバーシークレットが必要です。ZIP の上限は 2 MiB（非圧縮 4 MiB）で、各ソースには新しい順に完了済み 2 バージョンが保持されます。ダウンロードリンクは所有者を確認し、有効期限は 60 秒です。

## 同期、競合、バックアップ

初回サインインでは、コピーするローカル項目を選択します。コピーされた項目には新しい ID が付与されます。オフラインでの編集は端末キャッシュに残り、後で同期キューに入ります。同じソースが別の端末で変更された場合、停止するのはそのソースだけです。比較して、ローカルで上書き、クラウド版を採用、新しい下書きとして保存、のいずれかを選びます。アプリケーションが競合の勝者を黙って選ぶことはありません。

ソースを定期的にエクスポートしてください。サインアウト時はまず同期を試み、その後に独立したサインアウト済みローカルワークスペースを復元します。安全な復旧手順は[トラブルシューティング](./08-troubleshooting-and-acceptance.md)を参照してください。
